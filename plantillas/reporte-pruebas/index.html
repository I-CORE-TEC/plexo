    Reporte de Pruebas

    Plantilla

    Cierre formal de una ronda de pruebas. Documenta el resultado por criterio de aceptación, los defectos encontrados y la recomendación final (desplegar / repetir / rechazar).

    Metadatos

    Campo Valor
    Proyecto OSTEL — Implementación de PLEXO
    Caso base relacionado Login / Registro / etc.
    Issue de requerimiento #<N> — Título
    Issue de testing #<N>
    Fecha de ejecución YYYY-MM-DD
    Ejecutado por Nombre del tester
    Entorno Staging / Producción / Local
    Versión / Commit hash corto

    Resumen

    Criterios totales OK Fallaron Pendientes
    N N N N

    Resultado general

    Aprobado / Aprobado con observaciones / Rechazado

    Resultados por criterio de aceptación

    # Criterio Resultado Observaciones
    1 Descripción OK / Fallo / Pendiente Nota
    2 Descripción OK / Fallo / Pendiente Nota
    3 Descripción OK / Fallo / Pendiente Nota

    Casos probados

    • Flujo principal (camino feliz)
    • Validaciones de campos obligatorios
    • Manejo de errores y mensajes al usuario
    • Casos borde (valores límite, datos vacíos)
    • Regresión: funcionalidades existentes no afectadas
    • Permisos y acceso por rol

    Referencia al caso base

    Campo Valor
    Caso base Link o nombre del caso maestro
    Versión del caso base YYYY-MM-DD o versión
    Instancia actual Link a esta corrida

    Observaciones y defectos encontrados

    Defecto 1 (si aplica)
    • Descripción: Qué falla
    • Pasos para reproducir: Cómo se reproduce
    • Severidad: Alta / Media / Baja
    • Issue creado: #<N> (si se abrió un issue de bug)

    Evidencia

    Links a capturas, videos o logs de la ejecución de pruebas.

    Conclusión y recomendación

    Indicar si se puede desplegar, si hay items bloqueantes o si se requiere una nueva ronda de pruebas antes del despliegue.

    Publicación

    • Reporte publicado en i-core-tec.github.io/plexo
    • Aprobado por el cliente: Nombre y fecha, o "Pendiente de aprobación"
